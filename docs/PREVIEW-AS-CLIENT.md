# Смотреть страницу глазами клиента

Некоторые экраны выглядят **по-разному у разных клиентов**, потому что зависят от их
настроек — прежде всего от провайдера озвучки и от того, работает ли его ключ. Самый частый
пример: поле голоса на `/channels` и на странице создания. Если каталог голосов провайдера
загрузился, там выпадающий список; если нет — поле ручного ввода и строка с причиной.

Из-за этого «у меня выглядит не так, как я запушил» почти всегда означает **не ту ветку в
голове, а другой ключ в базе**. Прежде чем подозревать деплой, посмотрите вид клиента.

## Способ 1 — через интерфейс, две минуты

Самый быстрый, ничего не ломает:

1. Настройки → **Voiceover provider** = провайдер клиента (например `AI84`).
2. Вставить его API-ключ в соответствующее поле.
3. Открыть `/channels` — теперь видно то же, что видит он.
4. Вернуть провайдера обратно на свой.

Годится, когда нужно просто посмотреть. Своя база при этом меняется — не забудьте вернуть
настройку.

## Способ 2 — изолированная копия, свою базу не трогая

Когда менять свои настройки нельзя:

```bash
# отдельная папка с тем же кодом — Next 16 не поднимет второй dev-сервер из той же
# ("Another next dev server is already running")
git worktree add --detach /tmp/preview main
cp -al node_modules /tmp/preview/node_modules      # именно cp -al: симлинк ломает Turbopack

cd /tmp/preview
FACELESS_STUDIO_DATA_DIR=/tmp/preview-data npx next dev -p 3010
```

`FACELESS_STUDIO_DATA_DIR` даёт пустую базу — настройки клиента вносятся через
`POST /api/settings`, и своя `~/.faceless-studio/studio.db` не затрагивается вообще.

Убрать за собой:

```bash
git worktree remove --force /tmp/preview && rm -rf /tmp/preview-data
```

## Проверить, что запущено именно то, что запушено

```bash
git branch --show-current && git rev-parse --short HEAD && git status --short
git diff --stat origin/main origin/<ветка-клиента>   # пусто = файлы совпадают
```

Ветки могут стоять на **разных коммитах** и при этом содержать **одинаковые файлы** — так
бывает после мёржа: у `main` сверху появляется мёрж-коммит, а код тот же. Сравнивайте деревья
(`git rev-parse <ветка>^{tree}`), а не хеши коммитов.
